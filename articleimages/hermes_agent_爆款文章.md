## 二、先搞清楚这个项目是什么

在开始之前，先简单介绍一下我们今天要用的工具：**Hermes Agent**。

你可以把它理解成一个"AI中枢"：

```
你和AI之间需要一个翻译官，Hermes就是干这个的
它把你的消息翻译给AI听
再把AI的回答传回来
微信、飞书、网页……都能用它来连接AI
```

它部署在 **Hugging Face Spaces** 上——这是一个免费的云平台，相当于你租了一间虚拟办公室来放你的AI助手。

**整个过程不需要你写一行代码。**

## 三、我踩过的那些坑（血泪史）

### 3.1 第一个坑：Web界面彻底罢工

刚开始，项目自带了一个网页聊天界面，看起来挺正规的。

结果某天打开网页，AI助手完全不回复，日志里显示一个奇怪的错误：

```
connect ENOENT /tmp/hermes-agent-bridge.sock
```

什么意思？

> 打个比方：你的家里有两个房间，一个是"客厅"（网页界面），一个是"书房"（AI处理大脑）。两个房间之间有一扇门在传递消息。
>
> 现在这扇门消失了，客厅说的话传不到书房。

我尝试了各种方法修复：

| 修复次数 | 尝试方案 | 结果 |
|---------|---------|------|
| 第1次 | 给脚本添加执行权限 | ❌ 依然报错 |
| 第2次 | 手动创建符号链接指向正确路径 | ❌ 依然报错 |
| 第3次 | 适配新版bridge机制 | ❌ 彻底放弃 |

**根本原因**：这个Web界面依赖一个项目内部的私有通信机制，没有官方文档，每次更新都可能破坏修复。

### 3.2 第二个坑：微信突然不说话了

原本微信对话好好的，突然有一天AI完全不回复了。

排查半天发现，是AI模型供应商的名字变了：

- 之前叫 `siliconflow`
- 更新后只认 `custom`

**就像你去银行办业务，昨天报"SiliconFlow"还认识，今天必须报"custom"才搭理你。**

### 3.3 关键抉择：要不要放弃？

面对这些问题，我问了自己一个问题：

> 这个项目的核心价值是什么？

答案是：**通过多渠道与AI对话**。

- 微信和飞书能正常对话 → 核心价值保留 ✅
- Web界面用得很少 → 不是核心功能 ✅

**于是我做了一个决定：直接移除Web界面。**

## 四、重生后的架构有多简洁？

移除Web界面后，整个系统变得非常简单：

```
【旧架构】用户 → 前台(网页) → 传菜员(bridge) → 大脑(Gateway) → AI
              ↑                                    ↑
           这个老坏                             这个才是核心

【新架构】用户 → 微信/飞书 ──→ Gateway ──→ AI
                              ↑
                         就这一个核心
```

用餐厅来理解：
- **旧架构**：顾客 → 前台 → 传菜员 → 厨师。传菜员经常请假，导致上菜慢。
- **新架构**：顾客直接点餐，或者通过外卖平台 → 厨师。没有中间商，效率更高。

**好处立竿见影：**
- 故障点从3个减少到1个
- 部署时间从30分钟缩短到10分钟
- 再也不怕第三方更新破坏你的配置

## 五、微信配置：扫码就能用

### 5.1 方案选择

微信接入有两种方式：

| 方式 | 复杂度 | 需要的材料 |
|------|--------|-----------|
| 传统开发者模式 | 高 | 开发者资质、企业认证、服务器 |
| **iLink扫码** | 低 | **微信APP** |

我们选iLink，就像扫码登录网页版微信一样简单。

### 5.2 具体步骤

**第一步：启动容器**

部署项目后首次启动，系统会自动检测到没有微信Token，然后申请一个二维码。

**第二步：获取二维码**

访问你的Space地址 + `/files/weixin_login_qrcode.png`

例如：`https://你的名字-hermesagent.hf.space/files/weixin_login_qrcode.png`

> ⚠️ 注意：二维码有效期只有5分钟，需要尽快操作！

**第三步：扫码确认**

1. 打开微信 → 右上角"+" → "扫一扫"
2. 对准屏幕上的二维码
3. 点击确认登录

**第四步：等待系统自动完成**

系统会自动：
- 获取Bot Token
- 保存到配置文件
- 重启Gateway加载配置

整个过程**完全自动**，你只需要扫码这一个动作。

### 5.3 后续使用

以后每次重启容器，不需要重新扫码，Token已经保存好了。

**如果需要更换账号？**

在设置里添加环境变量 `FORCE_WEIXIN_RESCAN=true`，然后重建容器即可。

## 六、飞书配置：企业级体验

### 6.1 为什么飞书配置更复杂？

微信的iLink相当于"访客登记"，飞书则相当于"员工入职"——需要更多资料和权限。

但好处是：**一次配置，长期稳定**。

### 6.2 飞书开放平台配置

**第一步：创建应用**

1. 打开 [open.feishu.cn/app](https://open.feishu.cn/app)
2. 创建"企业自建应用"
3. 记录 **App ID** 和 **App Secret**

**第二步：启用机器人**

在应用后台 → 机器人 → 打开开关

**第三步：配置事件订阅**（最关键！）

1. 添加事件：`im.message.receive_v1`（接收消息）
2. 连接方式选择：**长连接（WebSocket）**

> 这相当于给机器人安装了一根"专线电话"，有消息来立即通知它。

**第四步：申请权限**

搜索并添加以下权限：
- `im:message:send_as_bot` - 发送消息
- `im:message` - 读写消息
- `im:chat:readonly` - 读取群信息

**第五步：发布应用**

创建版本 → 申请发布 → 企业管理员审批通过

**第六步：把机器人加入群聊**

飞书群 → 右上角"···" → 群机器人 → 添加机器人 → 搜索你的应用名

### 6.3 Hugging Face配置

在Space的Settings → Secrets中添加：

| 变量名 | 值 |
|--------|-----|
| `FEISHU_APP_ID` | cli_xxxxxxxxxx（你的App ID） |
| `FEISHU_APP_SECRET` | 你的App Secret |
| `FEISHU_CONNECTION_MODE` | websocket |

**验证是否成功：**

查看日志，出现以下内容表示连接成功：

```
[Lark] connected to wss://msg-frontier.feishu.cn/ws/v2?...
```
